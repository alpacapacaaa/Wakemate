# MVP 범위

확정: 2026-08-17.

이 문서는 **v1에 무엇이 들어가고 무엇이 안 들어가는지**를 정한다. `docs/api-contract.md`가 서버
계약의 *어떻게*라면 이 문서는 *어디까지*다. 둘이 어긋나면 이 문서가 이긴다.

> 클라이언트 경로는 모두 **`frontend/`** 기준이다 — `lib/store.ts`는 `frontend/lib/store.ts`를
> 뜻한다. 네이티브 쪽 사실은 `docs/alarmkit.md`에 따로 있다.

---

## 한 줄

> **친구 3~5명이 한 방에서 실제로 서로를 깨우고, 아침에 누가 누구 목소리로 일어났는지가 방에 남는다.**

iOS 26 실기기, 서울 시간대, 방 하나로 검증한다.

## 완료 기준

실기기 두 대에서:

1. 두 사람이 **서로 다른 시각**을 정하고
2. 각자 **다른 친구의 목소리**로 깨고 (녹음한 사람이 한 명뿐이면 그 목소리로)
3. 둘 다 "일어났어요"를 누르면
4. **양쪽 방 화면에 상대가 몇 시에 일어났는지 보인다**

4번은 서버 없이 불가능하다. 그래서 v1에 서버가 들어간다. 반대로 말하면, 서버는 4번과 "코드로 방에
참여" 두 가지를 되게 하는 데 필요한 만큼만 만든다.

## 확정된 결정

### 신원 — 로그인 없음

기기가 만든 user id + 서버가 발급한 토큰. Sign in with Apple은 v2로 미룬다.

- **대가**: 앱을 지우거나 기기를 바꾸면 계정이 사라진다. 친구 몇 명 규모의 검증에서는 감당한다.
- 나중에 SIWA를 붙일 때는 기존 계정에 연결하는 마이그레이션만 남는다.
- `expo-apple-authentication`은 현재 쓰이는 곳이 0곳이므로 의존성에서 제거한다.

### 목소리 — 한 번 녹음하고, 바꾸고 싶을 때 바꾼다

매일 녹음하지 않는다. 각자 목소리 하나를 갖고, 교체하면 **자기가 속한 모든 방에 반영**된다.

- 클라이언트는 이미 이렇게 동작한다 — `store.setMyVoice`가 내가 속한 모든 방의 내 멤버 레코드에
  같은 목소리를 미러링한다.
- 서버는 `POST /me/voice` 하나로 최신 목소리를 갱신하고, `Member.voiceUpdatedAt`을 보고 다른 기기가
  다시 내려받을 시점을 판단한다.
- **반영 지연**: 내가 목소리를 바꿔도, 나를 듣는 사람의 알람은 그 사람 앱이 다음에 포그라운드로 올
  때 새 파일을 받아 재예약해야 바뀐다. v1에 푸시가 없으므로 최대 하루 늦는다. 수용한다.

### 시각 — 멤버별

방은 *누구와 함께 일어나는지*이고, *몇 시에*는 각자의 것이다. 이미 그렇게 구현돼 있고
(`room.members[].alarm`), 다른 사람의 시각은 방 설정에서 읽기 전용으로만 보인다.

메인 화면(주간 덱)에서 요일 카드를 옆으로 스와이프해 내 아침을 켜고 끈다. 시각 편집은 요일을 열면
나오는 상세 화면.

### 목소리 배정 — 듣는 사람마다 다르게

`(room, member, date)`마다 서버가 **한 번 정하고 고정한다.** A는 B 목소리로, B는 C 목소리로 깬다.
방 전원이 같은 목소리를 듣는 방식은 채택하지 않았다.

- **왜**: 각자 시각이 다르면 "같은 목소리를 들었다"는 사실을 아무도 확인할 접점이 없어 공유감이
  전달되지 않는다. 그리고 그 목소리의 주인은 자기 목소리로 깨야 하는 모순이 생긴다.
- **규칙**: 나를 제외하고, **녹음을 마친** 멤버 중 균등 랜덤. 어제와 같은 사람은 되도록 피한다 —
  3명 방은 나를 빼면 2명이라 반복이 불가피하므로 보장이 아니라 선호다.
- 녹음한 멤버가 없으면 시스템 기본 사운드로 울린다. **알람이 울리지 않는 것은 어떤 경우에도
  허용하지 않는다.**
- 클라이언트의 `pickVoiceFor`는 서버 배정으로 대체되어 사라진다. 지금은 ring 화면이 다시 뽑기
  때문에 실제로 울린 목소리와 다른 사람을 공개할 수 있다 — 이 배정이 그 버그를 고친다.

### 방 — 나가기 + 방장 강퇴

- 방을 만든 사람이 **방장**이다. `Room.ownerId` — **지금 모델에 없는 필드이므로 추가해야 한다.**
- 누구나 스스로 나갈 수 있다 (이미 구현됨).
- **방장은 멤버를 강퇴할 수 있다** (신규).
- **방장은 나갈 때 다음 방장을 직접 지정한다.** 자동 이관하지 않는다 — 원치 않는 사람이 강퇴 권한을
  물려받는 일이 없어야 한다.
  - 이관은 별도 오퍼레이션(`PUT /rooms/{id}/owner`)이다. 나가기와 분리했으므로 **나가지 않고 방장만
    넘기는 것도 가능**해진다 (공짜로 얻는 것).
  - 서버는 방장이 후임 없이 나가려 하면 **409로 거부한다.** 단 방장이 마지막 한 명이면 후임이 없으니
    그대로 나가고 방은 삭제된다.
  - 클라이언트는 방장이 "나가기"를 누르면 **후임 선택 시트를 먼저 띄운다** — 새 화면 하나가 는다.
- **강퇴·탈퇴된 기기 쪽 처리**: 다음 포그라운드에서 `GET /rooms`가 그 방을 더 이상 내려주지 않고,
  그 방의 개별 엔드포인트는 403/404로 답한다. 앱은 로컬에서 그 방을 지우고 `cancelNativeAlarm`으로
  알람을 취소한다.
  → *대가*: 푸시가 없으므로 그때까지 그 방 알람이 한 번 더 울릴 수 있다.

### 초대 코드 — 7일 만료, 방장이 재발급

코드는 발급 후 **7일 뒤 만료된다.** 무기한 코드는 한 번 유출되면 아무나 들어올 수 있고, 방 설정
화면은 코드를 계속 보여주며 공유 버튼까지 갖고 있다.

- `Room.codeExpiresAt` 추가.
- 만료된 코드로 참여하면 **410 Gone** — 404(그런 방 없음)와 구분해야 클라이언트가 "코드가 만료됐어요,
  새 코드를 받아주세요"를 말할 수 있다.
- 재발급은 `POST /rooms/{id}/code`, **방장만.** 새 코드 + 새 만료 시각을 돌려준다.
  → *뒤집으려면*: 멤버도 친구를 부를 수 있게 하려면 이 제한을 풀면 된다. 코드 회전이 보안 동작이고
  강퇴 권한과 같은 자리라서 방장으로 묶었다.
- 방 설정 화면은 남은 기간을 보여주고(“6일 남음”), 만료 후에는 코드 대신 **새 코드 만들기**를 보여준다.
  만료된 코드를 그대로 띄워두는 것이 최악이다.

### 나가거나 강퇴된 사람의 지난 기록 — 지운다

그 사람이 그 방에서 남긴 기상 기록은 **삭제한다.** 나갔으면 흔적을 남기지 않는다.

- 남은 사람들의 과거 아침 중 그 사람 목소리로 깬 것은 `wokenByMemberId`가 **null이 된다** — 지울 수
  없는 남의 기록이면서, 이름을 그릴 수 없는 id를 남겨둘 수는 없기 때문이다.
- *대가*: 남은 사람 입장에서 그 아침은 "기본 사운드로 깼다"와 구분되지 않는다. 지난주 로그에 구멍이
  생기는 것을 받아들이는 선택이다.
- 클라이언트는 이미 절반을 한다 — `store.leaveRoom`이 로컬에서 그 방의 기록을 함께 지운다. 강퇴도
  같은 경로를 탄다.
- **강퇴는 되돌릴 수 없다.** 방장이 누군가를 내보내면 그 사람의 지난 아침이 방에서 사라지고, 새 코드로
  다시 들어와도 돌아오지 않는다. 강퇴 버튼은 이 사실을 말하는 확인 문구를 달아야 한다.

### 방 인원 상한 — 5명

서버가 참여 시점에 막는다(6번째는 409). 덱과 요일 화면이 편안하게 담는 범위이고, 배정에서 "어제와
같은 사람 피하기"도 나를 뺀 4명이면 무리 없이 돈다.

- 3명 방(나를 빼면 2명)은 여전히 이틀에 한 번 반복이 불가피하다 — 상한과 무관한 하한 문제다.
- 나중에 올리는 것은 쉽다. 내려가는 쪽이 어렵다.

### 유지 — 이미 있고 완전히 로컬이라 비용이 0

개인 알람(방 없는 알람), 스누즈(5/9/10/15분), 요일 반복과 1회성 알람. 그대로 두되 더 늘리지 않는다.

## 서버 표면 — 오퍼레이션 16개

```
POST   /me                            기기 등록 → { userId, token }.  토큰 만료 없음
PATCH  /me                            { name }
POST   /me/voice                      multipart .caf → { voiceUrl, voiceUpdatedAt }   변환 없음
GET    /voice/{userId}                .caf 바이트 — Bearer 인증. 같은 방 사람만

GET    /rooms                         내가 속한 방 전부 — 멤버·voiceUrl·각자 스케줄·ownerId
                                      포그라운드 갱신 경로. 여기서 사라지면 강퇴·탈퇴된 것
POST   /rooms                         { name } → Room + code + codeExpiresAt.  만든 사람이 방장
POST   /rooms/join                    { code } → Room.  만료 410, 없음 404, 정원·중복 409
PATCH  /rooms/{id}                    { name } — 방 이름 변경
POST   /rooms/{id}/code               코드 재발급 — 방장만. → 새 code + codeExpiresAt
PUT    /rooms/{id}/owner              { memberId } 방장 이관 — 방장만
PUT    /rooms/{id}/members/me/alarm   내 시각·요일 (전체 객체, 멱등)
DELETE /rooms/{id}/members/me         나가기 — 방장이 후임 없이 나가면 409 (혼자면 방 삭제)
DELETE /rooms/{id}/members/{memberId} 강퇴 — 방장만, 아니면 403

GET    /rooms/{id}/assignments?from&days=7   날짜별 { wokenByMemberId, voiceUrl }
                                      요청받을 때 없는 날짜만 뽑아 저장한다. 크론 없음
POST   /rooms/{id}/wakes              기상 기록. (room, member, date) 멱등
GET    /rooms/{id}/wakes?from&to      모닝 로그 — 방 전원의 기록
```

나가기·강퇴 두 곳에서 **그 사람의 기상 기록을 지우고, 남은 사람 기록의 `wokenByMemberId`를 null로
만든다.** 정원(5명)과 코드 만료는 `POST /rooms/join`에서만 검사하면 된다.

`docs/openapi.yaml`에 이 16개가 그대로 있다 (+ `POST /me/devices`는 v1 제외 표시만 해두었다).

테이블 다섯 개 + 목소리 파일 저장소. **DDL은 `docs/api-contract.md` §8에 있고, 유니크 제약 세 개가
이 명세의 핵심 규칙**이다 — 코드 유일성, 배정 고정, 기상 기록 멱등. 앱 코드로 구현하면 동시 요청에서
샌다.

만드는 순서는 `docs/api-contract.md` §9. 1단계(엔드포인트 4개)만 끝나도 **초대 코드로 친구가 실제로
방에 들어온다** — 지금 서버가 없어서 안 되는 것 중 가장 큰 것이다.

자세한 타입·에러·오프라인 규칙과 해피패스 예제는 `docs/api-contract.md`.

## 클라이언트에 남은 일

1. **`lib/store.ts` 16개 함수를 fetch로 교체.** 화면은 한 줄도 건드리지 않는다 — 이 파일은 그러라고
   만든 시임이다.
2. `pickVoiceFor` 제거 → 서버 배정 사용 (예약 시점과 ring 화면 모두)
3. **목소리 파일 다운로드 경로가 아직 없다.** `voiceUrl`을 Bearer 토큰과 함께 받아 로컬 파일로 쓰고,
   그 경로를 `AlarmKitModule.saveSoundToAppGroup`에 넘겨야 한다. 네이티브 쪽은 **파일 경로**를 받으므로
   메모리에 든 바이트로는 안 되고, 파일로 쓰려면 `expo-file-system`을 **의존성에 다시 넣어야 한다**
   (지금은 아무도 import하지 않아 제거된 상태이고, expo가 간접 의존해 설치만 되어 있다).
4. `Room.ownerId`·`Room.codeExpiresAt` 추가, `store.removeMember`, `store.transferOwner`
5. 방 설정 화면: 강퇴(방장에게만 보임), **나가기 전 후임 선택 시트**(방장이고 혼자가 아닐 때),
   코드의 남은 기간과 만료 상태, **새 코드 만들기**(방장에게만)
6. 참여 화면: 410(만료)을 404(없는 코드)와 다른 문구로 — "코드가 만료됐어요"
7. 목소리 교체 시 재예약, 403/404 응답 시 로컬 방 제거 + 알람 취소
8. **App Group 음성 파일이 무한 누적된다** — `cleanupOldSounds`를 JS에서 아무도 부르지 않고, 부른다
   해도 파일명 규칙이 어긋나 있다 (JS는 `voice_<base36>.caf`, Swift는 `voice_YYYYMMDD.caf` 8자리만
   인식).

안 쓰는 네이티브 의존성 정리(`expo-apple-authentication`, `expo-notifications`,
`expo-secure-store` + `app.json`의 `usesAppleSignIn`·`UIBackgroundModes`)는 완료했다.

## 범위와 무관하게 먼저

**번들 ID 확정**(`CHANGEME` 4곳: `app.json`의 bundleIdentifier·App Group,
`AlarmKitModule.swift`, NSE 참조 파일) **→ 실기기 1회 검증.**

확인할 것: 알람이 실제로 울리는지, 녹음한 목소리가 알람음으로 재생되는지, 스누즈가 AlarmKit
countdown으로 다시 울리는지, **같은 alarm id 재예약이 교체인지 에러인지.**

여기서 결과가 다르면 배정 설계가 바뀐다. 시뮬레이터로는 넷 다 검증할 수 없다.

## 미결

앞서 열려 있던 네 개(방장 이관·초대 코드 수명·지난 기록·인원 상한)는 2026-08-17에 모두 확정해 위
「확정된 결정」에 넣었다.

### 확정들이 겹쳐서 생긴 구멍 하나

**방장이 사라지면 그 방은 아무것도 할 수 없게 된다.** 로그인이 없어 앱을 지우거나 기기를 잃으면 계정이
사라지는데, 이관은 자동으로 일어나지 않고 코드 재발급과 강퇴도 방장 전용이다. 그러면 남은 사람들은
새 사람을 부를 수도, 내보낼 수도, 방장을 세울 수도 없다. 코드까지 7일 뒤 만료되므로 그 방은 사실상
닫힌다.

v1에서는 **방을 새로 만드는 것으로 감당한다** — 5명이 서로 아는 사이라 다시 모이는 비용이 낮고, 잃는
것은 지난 아침 기록이다. 값싼 완화책이 필요해지면 둘 중 하나:

- 방장이 **N일(예: 14일) 접속하지 않으면** 남은 멤버 중 가장 오래된 사람에게 이관을 허용한다 — 서버가
  `lastSeenAt`만 들고 있으면 된다
- **코드 재발급만** 멤버 전원에게 허용한다 (강퇴·이관은 방장 전용 유지)

### 실기기 검증이 답할 것

1. **같은 alarm id 재예약이 교체인가** — 아니면 `cancel` → `schedule` 두 단계로 바꿔야 한다
2. **스누즈 버튼 카피를 앱이 지정할 수 있는가** — iOS 26.1에서 `stopButton`이 deprecated 되어
   시스템 기본 UI가 쓰일 가능성이 높다
3. **`.caf` 음성이 실제로 알람음으로 재생되는가** — 포맷은 맞췄지만 기기에서 확인한 적이 없다
